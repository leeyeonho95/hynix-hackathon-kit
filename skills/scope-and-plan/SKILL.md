# 범위 자르기와 계획

## PLAN.md 템플릿
```
# PLAN
## 목표 (한 문장)
## 하지 않을 것 (Won't)
## MVP 기능 (인수 기준 번호와 연결)
## 구조 (파일/폴더 트리 10줄 이내)
## 단계
1. [ ] 단계 이름 — 산출물 — 검증 방법(명령 또는 화면)
## 리스크와 대안
```

## 시간 배분 (과제 180분 기준)
- 0~25분: README 분석, 담당자 질문, REQUIREMENTS.md
- 25~40분: PLAN.md, 구조 결정, DECISIONS.md 시작
- 40~140분: 단계별 구현 + 단계마다 실행 확인
- 140~165분: 전체 검증, 버그 수정, 화면 다듬기
- 165~180분: README 실행법, EXPLAIN.md, 최종 제출
- 140분 시점에 Must가 안 끝났으면 Should를 버린다.

## 과설계 점검 (구현 전에 하나씩 묻기)
- 이 구성요소는 어떤 인수 기준 때문에 필요한가? 답이 없으면 뺀다.
- 읽기만 하는 기능인데 쓰기 방어/동시성 처리를 넣고 있지 않은가?
- 데이터가 수백 건 수준인데 DB 서버, 캐시, 큐를 쓰고 있지 않은가?
- 사용자 1명 데모인데 인증/권한을 만들고 있지 않은가?
- 프레임워크 하나로 될 일을 두 개로 나누고 있지 않은가?

## 아키텍처 기본값
- 화면 필요: 정적 HTML/JS 또는 Vite+React 하나
- API 필요: FastAPI 또는 Express 하나
- 저장: JSON 파일 → 필요하면 SQLite
- 바꾸려면 DECISIONS.md에 이유를 적는다.
